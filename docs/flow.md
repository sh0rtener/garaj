# Git Flow

Для разработки проекта используется упрощённая модель Git Flow.

Основная идея простая: `main` содержит стабильную версию приложения, а вся текущая разработка происходит в `develop`.

## Основные ветки

### `main`

Стабильная версия проекта.

В эту ветку попадает только готовый и проверенный код. Прямые изменения в `main` не вносятся — изменения попадают сюда через Pull Request.

### `develop`

Основная ветка разработки.

Здесь находится актуальная версия проекта, над которой ведётся работа. Все новые функции и обычные исправления начинают свой путь отсюда.

## Временные ветки

### `feature/*`

Используется для новых возможностей.

Например:

```text
feature/auth
feature/task-management
feature/employee-management
```

Ветка создаётся от `develop`. После завершения работы создаётся Pull Request обратно в `develop`.

### `bugfix/*`

Используется для исправления ошибок, найденных во время разработки.

Например:

```text
bugfix/task-status
bugfix/invalid-login
```

Работа также начинается от `develop` и после завершения вливается обратно в `develop`.

### `release/*`

Используется, когда очередная версия готовится к выпуску.

Например:

```text
release/1.0.0
```

На этом этапе новые функции уже не добавляются. Ветка нужна для финальной проверки, исправления найденных проблем и подготовки версии.

После этого она вливается в `main`, а затем изменения возвращаются в `develop`.

### `hotfix/*`

Используется для срочных исправлений уже выпущенной версии.

Такая ветка создаётся непосредственно от `main`.

Например:

```text
hotfix/auth-error
```

После исправления ветка вливается одновременно в `main` и `develop`, чтобы исправление не потерялось в следующей версии.

## Как выглядит обычная разработка

В большинстве случаев работа выглядит так:

```text
develop
   │
   ├── feature/auth
   │
   ├── feature/tasks
   │
   └── bugfix/task-status
           │
           ▼
        develop
```

Когда набирается достаточно изменений для новой версии:

```text
develop
   │
   ▼
release/1.0.0
   │
   ├── исправления
   └── финальная проверка
   │
   ▼
main
   │
   ▼
v1.0.0
```

Если в production обнаруживается критическая ошибка:

```text
main
 │
 └── hotfix/critical-error
          │
          ├──→ main
          │
          └──→ develop
```

## Pull Request

Все изменения, которые попадают в `main` или `develop`, проходят через Pull Request.

Перед merge должны пройти автоматические проверки проекта: сборка, тесты и остальные проверки, настроенные в GitHub Actions.

Название ветки должно коротко описывать то, над чем ведётся работа:

```text
feature/task-management
bugfix/task-status
release/1.0.0
hotfix/auth-error
```

Не стоит создавать ветки с названиями вроде:

```text
test
new
fix
my-branch
```

Название должно позволять понять назначение ветки без необходимости открывать её.
